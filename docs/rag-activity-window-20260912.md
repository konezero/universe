# RAG 활동 구간 수집 (2026-09-12)

## 확인한 원인

memory_source_window는 활동이512개를 넘으면 FAST_EXTRACT_SOURCE_TOO_LARGE로 소스 전체를 제외했다. Observer의 semantic extraction은 전체32,000자/256개 발췌 한도에서 나머지를 자르고, 이후 같은 역할 발췌를 합쳐2,000자로 다시 줄였다. 소스 순환 커서만으로는 이 뒤의 활동을 이어서 추출할 수 없었다.

## 변경

자동 수집은 활동 ordinal 순서로512개 이하의 구간을 선택한다. 발췌 한도에 걸리면 구간을 줄여 다시 검증한다. 본문이 없는 구간 뒤에 의미 있는 활동이 있으면 다음 구간까지 탐색한다. 미처리 활동이 남으면 같은 소스의 마지막 처리 activity_id/digest/ordinal을 재개 위치로 저장한다. 다음 호출은 해당 기준 활동이 여전히 일치하는지 확인한 뒤 그 다음 활동부터 시작한다.

Host가 선택한 구간만 내부 인자로 실제 추출에 전달하며 HTTP 요청의 사용자 지정 활동 구간은 받지 않는다. 실행 직전에 원본 등록 소스와 선택한 활동 참조를 다시 검증한다. 원문이나 활동 좌표가 달라진 경우 새 위치를 추측하지 않고 typed error로 반환한다. 이어 수집 중인 소스가 비활성화되거나 기준 활동이 없어져도 자동으로 커서를 초기화하지 않는다.

자동 구간 추출은 require_complete 경로를 사용한다. 긴 메시지는2,000자 이하 발췌로 나누며 역할이 같다는 이유로 다른 활동의 텍스트나 근거를 합치지 않는다. 기존 기본 Observer 호출의 동작은 유지한다. 비밀정보 마스킹은 발췌를 나누기 전에 적용한다.

커서는 같은 프로젝트의 COMPLETED 추출 실행에만 반영한다. SQLite 쓰기 트랜잭션에서 이전 run_id도 비교하여 뒤늦은 실행이 최신 커서를 덮어쓰지 못하게 한다. 전체 활동 구간 목록은 호출 중에만 보관하고 커서 JSON에는 저장하지 않는다. UI는 ‘대용량 소스 이어 수집 중’과 마지막 활동 번호를 표시한다.

## 한계와 후속

단일 활동의 마스킹 후 본문 자체가32,000자 또는256개 발췌를 넘으면 아직 활동 내부 재개 위치를 만들지 않는다. 처음 만나는 소스에서는 SEMANTIC_EVIDENCE_WINDOW_LIMIT로 제외 사유를 표시하고, 이미 이어 수집 중인 소스에서는 중단해 기존 커서를 보존한다. 원문 불일치 복구는 별도다. 비-Codex 입력은 이후 [Claude·Grok 소스 확장](rag-multi-source-20260912.md)에서 구현·검증했다.

활동 구간을 끝까지 순회하는 것과 AI가 모든 핵심 지식을 후보로 추출하는 것은 다른 검증이다. 새로운 텍스트 근거 분할은 지원하지만 의미적 완전 수집·모델 품질·자동 채택을 보장하지 않는다. 소스 순환이 한 바퀴 돌면 재검토할 수 있으며 전역 이벤트의 영구 exactly-once Collector를 구현했다는 의미가 아니다.
