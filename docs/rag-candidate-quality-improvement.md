# RAG 후보 품질개선 노드

## 목적

원본 메모를 그대로 Goal이나 RAG 지식으로 승격하지 않는다. 메모는
관찰 단위로 수집하고, 서로 관련된 메모를 근거와 함께 묶어 사람이
검토할 수 있는 후보 묶음(candidate dossier)을 만든 뒤에만 제안한다.

## 목표 흐름

```text
원본 메모
  -> 원자 사실/엔티티 추출
  -> 정규화와 중복 제거
  -> 관련 메모 클러스터링
  -> 공통 주장과 관계 조합
  -> 후보 묶음 생성
  -> 근거/충돌/품질 게이트
  -> 제안 및 검토
  -> Goal 승격
```

## 후보 묶음 계약

후보 하나는 단일 메모가 아니라 다음 정보를 포함해야 한다.

- 후보 제목과 한 문장 요약
- 연결된 원본 메모와 근거 구간
- 공통 엔티티, 주제, 시간 범위와 관계
- 반복 관찰 횟수와 독립 출처 수
- 중복·충돌 여부와 충돌 근거
- 추론과 직접 관찰의 구분
- confidence, 누락된 근거, 다음 확인 질문
- 제안 상태(`REVIEW_REQUIRED`, `KEEP`, `REJECT`, `CONFLICT_REVIEW`)

단어가 우연히 겹친다는 이유만으로 메모를 결합하지 않는다. 동일한
엔티티·상황·시간 맥락과 설명 가능한 관계가 있어야 조합한다.

## 품질 게이트

1. 짧은 상태 로그, 단순 실행 잡음, 비어 있는 내용은 후보화하지 않는다.
2. 동일 내용은 하나의 근거 묶음으로 합치고 반복 횟수를 보존한다.
3. 독립 근거가 부족한 후보는 제안하지 않고 보류한다.
4. 상충하는 근거가 있으면 자동 승격하지 않고 `CONFLICT_REVIEW`로 보낸다.
5. 후보가 `REVIEW_REQUIRED`를 통과하기 전에는 Goal을 생성하거나 자동
   `KEEP`하지 않는다.
6. 모든 제안은 원본 메모로 역추적할 수 있어야 한다.

## RAG 품질 검증

후보 묶음은 검색 가능한 근거와 함께 저장한다. 고정 질문 세트로
recall, precision, 근거 인용 정확도, 중복 검색률을 측정하고, 후보가
없는 경우와 충돌하는 경우를 별도 평가한다. 기존 스케줄러·lease·retry
동작과 이 품질 계층은 분리하되, scheduler는 후보 묶음 생성 stage의
성공/실패와 재시도를 동일한 durable 결과로 기록해야 한다.

## 완료 기준

- 여러 메모에서 하나의 후보 묶음을 만들고 각 근거를 보존한다.
- 중복·충돌·근거 부족 후보가 품질 게이트에서 구분된다.
- 후보는 검토 가능한 제안으로 노출되고, 검토 전 Goal 승격이 차단된다.
- 정상·빈 입력·충돌·idempotent replay를 검증하는 테스트가 있다.
- 기존 메모 수집과 scheduler의 lease/retry 계약을 깨뜨리지 않는다.
