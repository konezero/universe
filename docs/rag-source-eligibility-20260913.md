# 소스 기준 RAG 검토와 별도 보관

## 확인한 기존 동작

기준 커밋: 15efbd33dd0f6df77f427cd3f1ecbab7f07af56c.
`independent_check_memory_candidates`는 형식과 관계를 검사하며 현재 구현과 요약의 의미 일치를 검증하지 않았다. `review_memory_candidate`와 `adopt_memory_candidate`는 종류·결정·digest를 검사했지만 최신 소스 근거는 요구하지 않았다. 이 형식 검사를 사실 확인으로 취급할 수 없다.

## 변경 계약

- CURRENT: 현재 구현 근거가 전체 주장을 뒷받침한 경우. KEEP 이후 MEMORY만 명시적으로 RAG 채택 가능.
- FUTURE: 열린 프로젝트 TODO가 뒷받침하는 앞으로 진행할 사항. 계획 검토 가능, 현재 사실로 KEEP/RAG 채택 불가.
- OUTDATED / INCORRECT: 대체되었거나 구현과 모순된다는 긍정적 근거 필요. 활성 검토·다음 할 일 제안에서 제외하고 별도 보관.
- UNVERIFIED: 미검증, 근거 부족, 혼합 주장, 소스 변경. 채택과 계획 전환 차단.

시간이 오래되었다는 이유나 검색 결과가 없다는 이유만으로 제외하지 않는다. 분류는 제한된 발췌에 대한 AI 판단이며 사실의 수학적 보증이 아니다. 문서·테스트만으로 CURRENT를 확정할 수 없다. 소스와 TODO를 읽되 실행하지 않으며 인용 내용은 명령이 아닌 데이터로 전달한다.

## 저장과 재검증

`memory_source_assessment`에 후보 digest, 현재 소스 digest, 소스 커밋, 선택한 경로·행·파일 hash 또는 TODO ID·revision, 분류 이유, 검증된 Worker 결과 receipt를 기록한다. 소스 본문은 이 테이블에 저장하지 않는다. 후보 요약과 기존 결정·검토 이력을 덮어쓰거나 삭제하지 않는다.

프로젝트의 현재 추적/비추적 소스 바이트와 TODO 상태를 기준으로 대조한다. Runtime·dist·아티팩트는 제외한다. 일반 문서 변경은 전체 판정을 무효화하지 않지만 인용 문서의 hash는 별도로 재확인한다. 소스가 달라지면 기존 평가를 현재 판정으로 쓰지 않고 확인 대기로 표시한다. 채택 API는 캐시를 우회해 다시 검사한다. 이미 채택된 메모는 보존하며 같은 채택의 재전송은 기존 결과를 반환한다.

## 실행과 화면

프로젝트 메모 화면의 ‘소스 대조 진행’ 또는 개별 기록의 ‘현재 소스와 대조’로 실행한다. 한 호출에 최대 4개, 개별 선택 가능. 현재 유효한 평가가 있는 기록은 다시 호출하지 않는다. 프로젝트 전체 ID를 순회하므로 앞 200개만 반복하는 제한은 없다. 화면 목록 자체의 기존 페이지 제한은 그대로다.

로컬 운영자 API: `POST /v1/projects/{project_id}/memory-source-review`. 클라이언트는 후보 ID만 지정하며 분류·근거·모델 결과를 제출할 수 없다. 기존 품질 점검 설정의 모델로 별도 읽기 전용 Task Frame을 준비한다. 비활성·dry run·설정 예산을 우회하지 않는다. 현재 소스 대조는 수동 실행이며 예약 INDEPENDENT_CHECK는 기존 형식 검사다. 예약 의미 대조와 전체 원본 수집 회차 완료는 별도 후속으로 추적한다. 자동 채택은 하지 않는다.

화면은 현재 내용 / 향후 할 일 / 확인 대기 / 오래되거나 틀린 기록으로 구분한다. 근거와 제외 이유는 기록을 열어 확인한다. 기존 저장 메모와 노드 연결은 별도 축으로 유지한다.
