## 결과를 해석할 때의 주의점

현재 저장 설정에는 모든 단계가 CODEX/gpt-5.6-luna로 보이지만, 후속 세 단계의 실제 실행은 규칙 처리이고 모델 호출이 없다. 서버 run_memory_batch는 fallback=DETERMINISTIC이면 공급자가 사용 가능하더라도 바로 규칙 경로로 간다. 설정 이름만으로 모델 실행을 추정하면 안 된다.

Bench의 Luna 관측 4개는 SUCCEEDED=4, validation_states.NOT_RUN=4이며 평균 실행시간은 약 94.88초다. 앞선 실제 수동 실행은 약 24초, 47초, 306초였지만 입력량과 내용이 다르므로 이를 모델 품질 편차나 모델 간 우열로 해석할 수 없다. 이전 실패 후 성공한 재시도도 있으므로 최종 실행 관측의 100% 성공률을 전체 시도의 성공률로 읽어서는 안 된다. 시도별 실패 이력과 Bench의 집계 분모를 연결할 필요가 있다.

비교 목록에는 codex-test/grok-test/gpt-test 등의 이름을 가진 기록과 다른 작업 기록도 함께 있다. provenance와 작업·입력 조건을 분리하지 않은 상태에서 실운영 모델 순위로 사용하면 안 된다. compare_skill_bench는 모델 그룹에서도 작업 종류/프로젝트/프롬프트/입력 크기의 동등성을 보장하지 않는다.

현재 실제 AI 배치 실행 경계는 FAST_EXTRACT + CODEX + gpt-5.6-luna + MAX로 제한된다. 다른 모델의 라이브 비교는 NOT_RUN이며 이 제한을 바꾸지 않고 설정만 바꾸어 호출하는 것은 유효한 비교가 아니다. 모델 지원을 늘리는 것과 Grok/Claude 활동 소스를 입력으로 지원하는 것은 별도 과제다.

## 보완 순서와 완료 기준

### 1. 실행 상태와 품질 표시 바로잡기 (우선)

- 모델 설정과 실제 executor/provider/model/effort를 별도 표시. 규칙 처리는 ‘AI 호출 없음’으로 고정한다.
- ‘품질 점검’은 현재 ‘형식·참조 점검’임을 명시하고 실제 내용 품질은 미검증으로 표시한다.
- Bench는 실행 성공률/스키마 통과/내용 품질/채택률을 별도 지표로 보여준다. 검증하지 않은 품질을 0점 또는 100점으로 변환하지 않는다.
- 실운영/격리 검증/출처 미확인 기록과 프로젝트·작업 범위를 명시하고 필터링한다. 과거 기록을 이름만 보고 삭제하지 않는다.
- 완료 기준: NOT_RUN 관측만 있는 모델은 품질 순위에 포함되지 않고, 화면에서 기록 수와 검증 수 및 실제 호출 여부를 한눈에 구분할 수 있다.

### 2. 후속 처리의 실질적인 내용 개선

- SYNTHESIZE의 정형 영어 후보를 실제 원문 근거가 있는 한글 요약·제안으로 대체한다. 지원 executor가 없으면 의미 분석 완료로 표시하지 않는다.
- CONSOLIDATE는 현재 정규화한 요약 문자열이 같은 후보와 명시적 관계를 처리한다. 표현이 다른 동의 내용·상반된 사실은 자동으로 판별한다고 가정하지 않는다.
- 원본/통합 후보의 계보를 유지하면서 사용자 검토 목록에 같은 내용이 단계별로 반복되는지 확인하고 묶어서 표시한다.
- 독립 내용 검토는 원문 지지 여부, 과거 상태의 현재 사실화, 관련성, 중복/모순, 유출·복사를 평가한다. 검토 결과는 후보·입력 digest에 결속한다.
- 완료 기준: 정형 placeholder가 최종 아이디어로 나오지 않으며, 근거 없는 주장은 보류되고 자동 RAG 채택/노드 확정은 발생하지 않는다.

### 3. 모델별 편차를 측정하는 통제된 비교

1. 추출 executor의 단일 모델 제한을 지원 capability 계약으로 분리한다. 최초에는 가능한 모델 2개만 등록하고 동일 Task Frame·출력 계약을 통과시킨다.
2. 원문 스냅샷/해시, 정답 근거, 프롬프트 버전, 출력 스키마, Runtime 버전, 모델 실제 식별자, effort를 고정·기록한다. 운영 커서를 움직이는 수집 배치를 비교 입력으로 사용하지 않는다.
3. 짧은 한글/긴 혼합 언어/중복/상반된 이력/오류 로그/근거 부족 사례를 포함한 작은 평가 세트를 만들고 각 모델에 동일 사례를 최소 3회 반복한다. 최초 표본은 탐색용이며 적은 표본으로 일반적인 우열을 확정하지 않는다.
4. 스키마 준수, 원문 근거 정확도, 핵심 항목 누락, 중복, 시간적 정확성, 한글 가독성, 채택 가능성을 사례별로 평가한다. 자동 검사와 모델을 가린 사람 검토를 구분한다. 독립 평가 모델을 쓰더라도 평가자 편향을 기록한다.
5. 같은 사례끼리 성공률/품질/지연/토큰·비용을 비교한다. 입력 길이와 재시도·quota·실패 단계도 포함하고 누락된 비용은 UNKNOWN으로 둔다. 중앙값·분포·표본 수를 우선 표시하고 부족한 표본의 꼬리 지연값은 확정하지 않는다.
6. 반복 편차가 큰 사례와 모델 간 불일치만 상위 모델 또는 사람에게 재검토시킨다. 실제 품질 기준과 예산을 통과한 뒤 자동 모델 선택에 연결한다.

모든 비교 출력은 검토 전용 격리 영역에 저장하고 운영 후보/Bench 실운영 통계와 혼합하지 않는다. 평가 반복은 별도 예산·호출 제한 안에서 수행한다.
